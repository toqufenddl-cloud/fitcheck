# 시연 순서 (FitCheck 실시간 파이프라인, D69)

이 컴퓨터 전용. 원문은 화면에서만 보고(사례 탭 '원문 보기', 기본 꺼짐) 발표 자료에는 cot_id와 상품명만 쓴다 (P10).

## 준비

1. Ollama 켜기 (근거 조항 검색용, 모델 `bge-m3`). 꺼져 있으면 4단계가 안내 후 gold 매핑으로 대체된다.
2. 앱 실행 (저장소 폴더에서):

   ```
   python -m streamlit run app/fitcheck_app.py
   ```

   (PowerShell에서 Activate.ps1이 실행 정책으로 막히면 venv의 python.exe로 바로 실행한다.)

   브라우저에서 http://127.0.0.1:8501 . 처음 열 때 데이터 판정 준비에 약 30초 걸린다.
3. 같은 흐름을 터미널로: `python -m src.fitcheck live --n 30 --as-of 2026-11-24` (저장값만: `--saved`, 특정 사례: `--ids 1547,2365,43`)

## 순서

| 순서 | 화면 | 보여줄 것 |
|---|---|---|
| 0 | 진단 결과 탭 | 원본·교정판 품질 점수와 등급(D70), 진단 의견, 등급 구간, 항목별 감점, 먼저 할 일 3개 |
| 1 | 실시간 분석 탭 | 기준일 2026-11-24, 분석 건수 30, '실시간', [분석 실행] |
| 2 | 1단계 기준 문서 검색 | KIS 준칙을 원본 URL로 받아 보관본과 해시 비교 (변경 없음 / 변경됨 / 접속 실패). 금소법·표준준칙은 보관본 사용과 시행일 |
| 3 | 2단계 규칙 생성 | 받은 준칙 제6조①에서 읽은 성향별 허용 등급표와 저장 표 비교. 같으면 "검색한 문서(KIS 준칙 제6조①, 시행 2026-09-21)의 등급표로 판정" |
| 4 | 3단계 상품 등급 검색 | 추천 상품만 상품명으로 조회(0.5초 간격, 진행률). 데이터 등급과 다른 상품 수, 사람 확인 등급 우선 |
| 5 | 4단계 근거 조항 검색 | 결함 유형별 상위 3개 조항(기준일에 시행 중인 것만)과 gold 조항 포함 여부 |
| 6 | 5단계 규칙 적용 | 점수 카드(데이터 기준 vs 최신 문서 기준)와 항목별 막대, 결함 수, ③ 판정이 바뀐 CoT, 근거 카드(문서·조항·시행일·검색 시각) |
| 7 | 사례 보기 탭 | 항목별 이행·미이행과 점수, 아래 세 사례를 하나씩. 필요하면 '원문 보기'를 켜고 끄기 |
| 8 | 전체 데이터 탭 | 7,201건 전체 판정(저장된 등급), 엄격판·교정판·근거 카드·manifest 내려받기 |

## 사례 cot_id

| cot_id | 유형 | 보여줄 것 |
|---|---|---|
| 1547 | 최신 등급으로 판정이 바뀐 것 | 적극투자형(허용 2–6). 신한골드증권투자신탁제1호[주식](A-u)가 데이터 2등급 → 최신 1등급(사람 확인 등급과 같음). 데이터 기준 범위 안 → 최신 기준 범위 밖 |
| 2365 | 범위 밖 | 위험중립형(공개 기준 4–6)인데 3등급 상품 2개 추천 → ③ 제외, 이관 문장 없음(이관 결함) |
| 43 | 위험등급 설명 누락 | 적극투자형, 추천 등급은 범위 안. answer에 위험등급이 없음(④ 기재 없음) → 교정판에 등급 문장 추가 |

## 실패할 때

| 상황 | 화면 표시 | 계속 여부 |
|---|---|---|
| 인터넷 끊김 | 1단계 '접속 실패', 3단계 '연속 2번 실패 → 저장값으로 계속' | 보관본 등급표·저장된 조회 결과로 계속 |
| 준칙 서식이 바뀌어 등급표를 못 읽음 | 2단계 '읽기 실패 → 저장 표로 판정' | 저장 표로 계속 |
| 읽은 등급표가 저장 표와 다름 | 2단계 '변경 감지, 승인 필요' | 승인 전이므로 저장 표로 판정 (D69) |
| Ollama 꺼짐 | 4단계 'Ollama가 응답하지 않음 → gold 매핑으로 대체' | gold 조항으로 근거 카드 작성 |

## 확인 기록 (2026-11-24)

- 인터넷 연결 상태 live 30건 1회: 파이프라인 326초(약 5분 26초), 데이터 판정 준비 포함 356초. 추천 상품 62개 실시간 조회(최신 등급 26개, 데이터 등급과 다름 14개). KIS 준칙 해시 변경 없음, 등급표 일치. ③ 범위 밖 CoT 데이터 기준 3 → 최신 문서 기준 15 (바뀐 CoT 12). 결과 `outputs/live/2026-11-24/`
- 인터넷 끊김(프록시를 닫힌 포트로 설정): 1단계 접속 실패 → 보관본, 3단계 연속 2번 실패 후 저장값으로 계속, 끝까지 실행
- Ollama 꺼짐(주소를 닫힌 포트로 설정): 4단계 안내 메시지 후 gold 매핑으로 대체, 끝까지 실행
- `streamlit run app/fitcheck_app.py --server.headless true`: http://127.0.0.1:8501 응답 200, `/_stcore/health` 200

## 외부용 시연 모드 (휴대폰·다른 컴퓨터에서 볼 때)

로컬 앱(`app/fitcheck_app.py`)은 그대로 두고, 외부에는 `app/fitcheck_public.py`만 연다. 앱은 127.0.0.1:8501에서만 듣고 ngrok 고정 도메인이 그 앞을 잇는다.

| 항목 | 외부용 모드 |
|---|---|
| 탭 | 진단 결과(저장 결과: 원본 → 교정판 점수, 항목별 감점, 주요 지표) · 실시간 검색(표본 30건) · 사례 보기(시연 6건) |
| 원문 | 원문을 읽는 코드 경로 자체가 없다. 파일 경로·상세 오류·내려받기도 없음 (단계 메시지의 경로·주소는 지운다) |
| 화면 출력 | 점수, 판정, 근거 조항(요지)·시행일, 추천 상품명과 데이터 등급 → 최신 등급(바뀐 상품 강조) |
| 접속 | 시작 화면 비밀번호 (`.streamlit/secrets.toml`의 `public_password`, git 제외). 세션당 5번 틀리면 1분 잠금 |
| 30건 실시간 검색 | CLI `live --n 30`과 같은 표본(고정 시드). 단계별 진행(st.status) ① 문서 ② 등급표 ③ 상품 등급 ④ 조항 ⑤ 판정, ⑤에서 상담별 행을 1건씩 추가(계산은 한 번에). 앱 전체에서 동시에 1개, 끝난 뒤 5분 간격. 기다리는 사람에게 남은 시간과 마지막 결과. 중간 실패 시 나머지 행은 저장값('저장값' 표시). 2026-11-25 1회 324.8초, 최신 문서 기준 64.4 미흡 (데이터 기준 71.9 보통) |
| 사례 보기 | 시연용 cot_id만: 1547, 2365, 43, 82(모든 항목 이행), 145(필수정보 일부 미확인), 5851(근거 부족으로 성향 확정). 개별 실시간 검색은 세션당 1분 1번, 30건 검색 중에는 쉼 |
| 디자인 | 보고서 스타일 (Noto Sans KR, 바탕 #F5F2EA, 주황 #FF5A1F·검정 칩, 검정 숫자 카드, 각진 카드·표). 테마는 run_public.ps1의 --theme.* 옵션 (로컬 앱 config.toml은 그대로) |
| 오류 | 일반 문구만 (`--client.showErrorDetails none`) |

준비 (한 번만):

1. ngrok 설치 (`winget install ngrok.ngrok` 후 `ngrok update`), ngrok 대시보드에서 authtoken 확인 후 `ngrok config add-authtoken <토큰>` (설정 파일은 `%LOCALAPPDATA%\ngrok\ngrok.yml`, 저장소 밖)
2. `.streamlit/secrets.toml`에 `public_password = "..."`, `ngrok_domain = "<내 고정 도메인>"`

실행 (로컬 앱이 8501을 쓰고 있으면 먼저 끈다):

```
powershell -ExecutionPolicy Bypass -File .\run_public.ps1
```

앱을 켜고 응답을 확인한 뒤 `ngrok http 8501 --url=<도메인>`(구버전은 `--domain`)을 연다. Ctrl+C로 터널을 닫으면 앱도 꺼진다.
