## D10. 상품명으로 데이터 연결 (CoT·소비자 → 상품 JSON)

- **관련도**: 높음 (03 적합성 일관성 판정: 추천 상품의 위험등급을 상품 JSON에서 가져올 때)

- **사실**
  - 상품 JSON은 10,000개인데 고유 `product_name`은 9,574개이다. 이름이 같은 상품이 있다.
  - CoT `product_names` 중 상품 JSON 이름과 정확히 일치하는 것은 76%이다.
  - CoT 4건은 `product_names`가 리스트가 아닌 깨진 문자열이다.
  - 소비자.csv의 `product_name`과 상품 JSON의 일치율은 아직 확인하지 않았다.
- **선택지**
  - (a) 정확히 일치하는 것만 사용
  - (b) 공백·괄호 정규화 후 매칭
  - (c) 중복 이름은 상품 유형 등 다른 키를 함께 사용
- **추가 사실 (02 노트북 6-4, 추천 상품명 22,050개 기준)**
  - 정확 일치 76.2% (증권이 대부분), 보험 `product_full_name` 일치 22.1%, 공백 차이 1.4%, 공백·괄호·기호 차이 0.0%(5건), 보험 모상품명 일치 0.0%(4건), 부분 일치·일치 없음 0.3%(64건)
  - 64건의 세부 원인: '본인→고객' 치환 의심(증권 31건), 상품명 조각(24건), 기타(9건)
- **결정**: 아래 순서로 매칭한다.
  1. 정확 일치: 증권은 `product_name`, 보험은 `product_full_name`
  2. 정규화(공백·괄호·기호 제거) 후 다시 비교
  3. 보험 모상품명(`mother_product_name`)으로 비교
  4. 그래도 남는 건은 원인 코드(예: 본인→고객 치환 의심 / 상품명 조각 / 기타)를 붙이고 '판정 불가'로 둔다
- **이유**: 실패의 대부분(22.1%)이 보험의 이름 컬럼 차이였고, 남은 실패는 원인별로 따로 볼 수 있게 남겨 두기 위해.
- **상태**: 확정 (2026-11-10)

## D12. 품질 진단 대상 CoT 범위

- **관련도**: 높음 (02~05 전체)
- **사실**
  - CoT는 Training 8,000건, Validation 1,001건으로 나뉘어 있다. Test 폴더는 받은 데이터에 없다.
  - 질문유형은 증권 3종(고객특성 강조형, 투자성향 및 조건기반형, 상품 비교 추천형)과 보험 3종(연령별·생애주기 저축성, 투자성 상품, 건강·질병보장 대비형)이다. 폴더 이름 기준이며, 유형별 건수는 아직 세지 않았다.
  - 새 문제 정의는 "투자상품 추천 시나리오"이다. 보험 3종 중 어느 것이 투자상품에 해당하는지는 불확실하다. 예를 들어 '건강 및 질병보장 대비형'은 투자상품이 아닐 수 있다.
  - 품질 기준 1·2(투자성향 판단)는 금융소비자보호법의 적합성 원칙에서 왔다(docs/sources.md 예정). 보장성 보험에도 같은 기준을 적용할 수 있는지는 확인이 필요하다.
- **선택지**
  - (a) 증권 3종만 진단
  - (b) 증권 3종 + 보험 '투자성 상품 추천형'
  - (c) 전체 6종을 진단하되, 유형별로 적용할 기준을 다르게
  - 그리고 Train과 Valid를 합쳐 9,001건 전체를 진단할지, 따로 볼지도 정해야 한다.
- **결정 (임시)**: 투자성 상품과 변액보험은 포함하고, 일반 보장성 보험은 제외한다.
- **아직 정할 것**
  - 이 기준을 질문유형(폴더)으로 적용할지, 추천 상품의 유형(상품 JSON의 보험 종류, 예: `변액`)으로 적용할지
  - Train과 Valid를 합칠지
- **상태**: 임시 (2026-11-10). 02 노트북 7단계(보험 상품 JSON 위험등급 확인) 결과를 보고 확정한다.
- **갱신 (2026-11-11)**: D18로 확정되었다. 적합성 진단은 증권 시나리오만 대상으로 한다.

## D13. cot2 허용 등급 파서 오류 발견과 수정

- **관련도**: 높음 (기준 3 적합성 일관성 판정의 입력값)
- **사실 (02b 노트북 추가 확인 A1·A2, 증권 CoT 7,201건 / 추천 상품 16,834건)**
  - 수정 전 파서(`src/extract.py`의 `parse_allowed_grades`)가 cot2의 허용 등급을 잘못 읽었다.
    - "위험등급 2부터 6등급까지" → {6}, "2등급부터 6등급까지" → {2, 6}
    - "허용 위험등급: 3, 4, 5, 6"처럼 끝에 '등급'이 없는 목록, "2,~6등급", "2～6" 표기를 인식하지 못함
    - 성향 범위를 적은 문장에 '허용·가능' 같은 단어가 없으면 그 문장을 건너뛰고, 다른 문장의 "2등급 상품 허용"을 허용 집합으로 잡음
  - 수정 내용: 범위·목록 표현(~, 부터~까지, 에서~까지, 쉼표·가운뎃점 목록)을 우선으로 읽고, 근거 종류(범위·목록 / 까지 해석 / 이상·이하 해석 / 단일 등급만 / 실패)를 함께 돌려준다.
  - 수정 전 → 후 핵심 숫자 (추천 상품 기준)
